# ADR-004 — Локално хранилище: IndexedDB

**Статус:** Accepted (2026-07-14; вписано по PD-019 границата — беше маркирано като "инженерна препоръка без дом" в PHASE_3_REVIEW §7.2)
**Отговаря на:** "Къде живеят данните локално?" — решено в 21 §5.2.

## Контекст

PD-012 стъпало 1: local-first, продуктът работи пълноценно без мрежа и без акаунт. SurfaceRepository.save() изисква атомарен запис на цялото aggregate дърво (INV-3, 21 §5.1). Проектът е самодостатъчен — изходните Image/PDF файлове се пазят вътре (11 §7).

## Решение

**IndexedDB** за структурираните данни + blob съхранение (изходни файлове). Пред localStorage: structured clone на вложени обекти, транзакции (нужни за атомарността), капацитет за PDF/изображения. File System Access API остава опция за blob слоя — Phase 4 преценка, зад същия `StorageAdapter` интерфейс (23 §4).

## Последици

- `StorageAdapter.transaction()` (23 §4) мапва директно на IndexedDB транзакции.
- Contract тестът (22 §7) се изпълнява срещу fake и срещу реалната имплементация еднакво.
- Storage quota грешки са реален път (23 §8: `StorageQuotaExceededError`) — UI error state за тях е задължителен, не теоретичен.
- Замяна на IndexedDB не изисква PD (PD-019: "как", не "какво") — само нов adapter, минаващ същия contract suite.
