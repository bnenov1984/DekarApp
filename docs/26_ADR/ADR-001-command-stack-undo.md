# ADR-001 — Command Stack за Undo/Redo (не Event Sourcing)

**Статус:** Accepted (PD-018 Условие A, 2026-07-14)
**Отговаря на:** "Как се имплементира Undo?" — въпрос, изрично отложен от 14 §5 и 18 §7, решен в 21 §4.

## Контекст

INV-12 (14 §4): всяка команда освен изтриване на проект има inverse. Undo историята е сесийна (11 §7). Shape/Calibration са Value Objects, заменяни изцяло (14 §3). Колаборация няма в v1 (PD-012).

## Решение

**Command Pattern с explicit inverse**, глобален стек per Project session (не per Surface). Всяка Core мутация се обвива в `Command<T>` (23 §3.2) с `do()`/`undo()`; `ProjectDeleteCommand` не имплементира интерфейса — INV-9 compile-time.

Отхвърлено: Event Sourcing — печели при трайна история (не се изисква), при collaborative merge (изключен от PD-012), и не носи нищо при VO-замяна семантика (старата стойност вече е в паметта на командата). Пълна обосновка: 21 §4.1.

## Constraint: Bounded Undo (PD-018 Условие B)

**Архитектурно задължително:** Undo стекът е **ограничен**. Границата е дефинирана като constraint, не имплементация:

- Стекът има горна граница по **брой операции ИЛИ паметен бюджет** (Engineering избира механизма и стойностите).
- При достигане на границата, **най-старите команди се евиктват първи** (FIFO от дъното на past стека).
- Евикция никога не нарушава INV-12 за задържаните команди — всичко в стека остава пълноценно обратимо; евиктнатото просто вече не е достижимо през Undo.
- Евикцията е тиха (без UI прекъсване); ако Engineering прецени, най-ранната достижима точка може да се комуникира ненатрапчиво.

Обосновка на constraint-а: freehand фигури с хиляди точки × дълга сесия → неограничен паметен растеж (PHASE_3_REVIEW §5). Продуктовото обещание "Undo покрива всичко" (US-015) се чете като "в рамките на разумната работна сесия", не "неограничено назад" — сесийната природа на историята (11 §7) вече поставя по-силна граница така или иначе.

## Последици

- CommandStack е Application-layer компонент; Core не знае за него (21 §4.3).
- Всеки нов Command тип изисква T-INV-12 round-trip тест преди merge (22 §3).
- Ако колаборация влезе в обхват (P-04+), това ADR се преразглежда изцяло, не се кърпи.
