# ADR-009 — Публична начална страница на корена на адреса, SPA под `/app/`

**Статус:** Accepted (Engineering, 2026-11-15)
**Отговаря на:** „Как се сервира публичната страница по PD-026 заедно със SPA-то?" — допълва [ADR-008](ADR-008-frontend-hosting.md), чието „приложението се сервира от корена на домейна" престава да важи буквално. Хостингът (Render Static Site, `render.yaml`, деплой след зелен CI) не се променя.

## Контекст

- PD-026: коренът на живия адрес е публична страница за аудиторията по PD-022; приложението се отваря от `/app/`.
- SPA-то няма URL routing (2 екрана + overlays, ADR-006) и не трябва да получи такъв заради една маркетингова страница.
- Публичната страница трябва да се индексира и да се чете без JavaScript — статичен HTML, не Svelte компонент.
- IndexedDB (ADR-004) е обвързан с origin, не с път — смяна на пътя на приложението не губи локални данни.
- Render Static Site сервира `index.html` на директория без конфигурация (directory index).

## Решение

**Vite multi-page build с два HTML входа** (`vite.config.ts`, `build.rollupOptions.input`):

| Вход | Файл | Сервира се на |
|------|------|---------------|
| `landing` | `src/ui/index.html` — статична страница, inline CSS, без `<script>` | `/` |
| `app` | `src/ui/app/index.html` — SPA-то, непроменено освен местоположението | `/app/` |

- `base: '/'` остава — asset пътищата са абсолютни (`/assets/…`) и работят и от `/app/`.
- Никакви rewrite/redirect правила в `render.yaml`: `/app/` се обслужва от directory index.
- Всички вътрешни линкове към приложението са `/app/` **с крайна наклонена черта** — не се разчита на redirect от `/app`.
- `npm run dev` сервира и двете от едно дърво: `http://localhost:5174/` и `http://localhost:5174/app/`.
- Дизайн референцията `docs/mockups/landing_page_dekar.html` е копие, не import: при промяна на съдържанието двете се поддържат ръчно в синхрон (коментар в `src/ui/index.html`).

## Отхвърлени алтернативи

| Опция | Защо не |
|-------|---------|
| **Landing като екран в SPA-то** (`/` показва маркетинг, после Home) | Внася routing в SPA-то (ADR-006), изисква JS за първата страница, смесва маркетинг и продукт в един bundle. |
| **Отделно repo/хост за сайта** (`www.`) | Повече операционна повърхност за solo екип (същата логика като ADR-007/008). Естествена следваща стъпка при собствен домейн с `www.` / `app.` поддомейни — тогава нов ADR. |
| **Redirect на Render от `/` към `/app/`, landing другаде** | Обратното на PD-026. |
| **Приложението остава на `/`, landing на `/landing`** | Посетител без линк вижда празно платно вместо обяснение какво е продуктът — точно проблемът, който PD-026 решава. |

## Последствия

- ADR-008 получава бележка към „Решение": коренът е публичната страница, SPA-то е под `/app/`.
- README: dev адреси и описание на деплоя.
- Бъдещ `app.` / `api.` поддомейн сетъп (ADR-008 „отворено") може да върне SPA-то на корена на `app.` — тогава ADR-009 се надгражда, не се заобикаля.
- Preview конфигурацията `.claude/launch.json` (`areaflow-ui`) отваря `/` — т.е. landing-а; приложението е на `/app/`.
