## §1. UX Architecture

### 1.1. Три слоя

```
┌─────────────────────────────────────────────┐
│  SHELL — рамката на приложението            │
│  Home, проекти, workspace switcher,         │
│  marketplace, настройки, акаунт             │
├─────────────────────────────────────────────┤
│  STUDIO — редакторът (95% от времето)       │
│  Canvas + Tool Dock + контекстни панели     │
├─────────────────────────────────────────────┤
│  SYSTEM — междуслойни услуги                │
│  Command Palette, известия, offline статус, │
│  undo/redo, AI асистент                     │
└─────────────────────────────────────────────┘
```

**Обосновка:** Shell/Studio разделението пази Studio минимален (Simplicity First) — нищо административно не живее в редактора. System слоят е достъпен отвсякъде, защото Command Palette (P6) е механизмът, който прави минималния chrome откриваем.

### 1.2. Обектен модел (менталният модел на потребителя)

```
Project
 └── Surface (1..n)  ← "върху какво меря": карта / изображение / PDF страница
      ├── Calibration / Georeference  ← първокласен обект, не настройка
      └── Measurement (0..n)          ← първокласен обект
           ├── Geometry (polygon/rect/circle/curve/freehand/line)
           ├── Computed values (area, perimeter, distance, angle…) ← Measurement Engine
           ├── Identity (име, цвят, група, бележка)
           └── Provenance (ръчно / AI-предложено / import)
```

**Ключово решение — "Измерването е обектът":** Потребителят не "чертае фигура и после пита за площ". Всяка фигура *е* измерване: стойността се вижда по време на чертане и остава като жив етикет (MeasurementChip) върху фигурата. **Обосновка:** Visual First; директна диференциация от SketchAndCalc (07, §10); премахва цяла категория UI ("покажи резултати") — резултатът никога не е另 място.

**Provenance** съществува, защото AI guardrail-ът изисква одитируемост: AI-създадено измерване носи траен badge (§18).

### 1.3. Режими — колкото се може по-малко

Единственият истински "режим" е активният инструмент. Няма edit mode / view mode, няма модове по повърхност. Изключение: **Ghost state** на AI предложения (§18) — визуално неприемливо да е неотличим.

**Обосновка:** режимите са основният източник на "къде съм и защо не работи" объркване (AutoCAD анти-модела). Excalidraw доказва, че tool-as-only-mode стига.

## §2. Information Architecture

### 2.1. Йерархия на съдържанието

```
AreaFlow
├── Home
│   ├── Recent projects (карти с preview)
│   ├── Start: On a map / Import a file / Blank canvas
│   └── Templates (Workspace-зависими) [след v1]
├── Studio (Project)
│   ├── Canvas (Surface tabs при >1 повърхност)
│   ├── Tool Dock
│   ├── Left Panel: Measurements (списък) + Layers
│   ├── Right Panel: Properties (контекстен) / Extensions
│   └── Status Bar: scale, units, zoom, snap, sync
├── Overlays (не са екрани)
│   ├── Command Palette (⌘K)
│   ├── Extension Marketplace
│   ├── Export / Report preview
│   ├── Workspace switcher (popover)
│   └── Settings
└── Account (минимален)
```

### 2.2. Панелна таксономия — кой панел за какво отговаря

| Регион | Съдържание | Кога се вижда |
|--------|-----------|---------------|
| **Ляв панел** | Данните: Measurement List (P4), слоеве, повърхности | Скрит до първото измерване; след това достъпен, състоянието се помни |
| **Десен панел** | Контекстът: свойства на селекцията ИЛИ активното extension | Само при селекция / активен инструмент с опции / отворено extension |
| **Долен dock** | Действията: инструменти за чертане | Винаги |
| **Горна лента** | Идентичността: проект, workspace, share/export, акаунт | Винаги (тънка) |
| **Статус лента** | Истината: мащаб, единици, zoom, snap, offline | Винаги (тънка) |

**Обосновка:** ляво=данни / дясно=контекст / долу=действия е разпределение, което остава стабилно във всички workspaces — workspace сменя *съдържанието* на панелите, никога *местата* им (§19). Мускулната памет е защитена.

## §3. Navigation Structure

**Плоска до крайност: 2 екрана + overlays.** Home ⇄ Studio. Всичко останало е overlay върху текущия контекст.

- Home → Studio: клик на проект или Start действие. 1 клик.
- Studio → Home: логото/back. 1 клик. Проектът се пази автоматично (без "Save?" диалог — undo историята покрива връщането).
- Marketplace, Settings, Export: overlays със `Esc` за затваряне; URL-адресируеми (deep links за PWA).
- Command Palette (⌘K / Ctrl+K): достъпен навсякъде; търси действия, инструменти, измервания по име, workspaces, extensions, help.

**Обосновка:** Всяко ниво навигация е данък върху "Minimal clicks". Bluebeam/ArcGIS показват как дълбочината убива увереността. Overlay моделът пази пространствения контекст на потребителя — той никога не "напуска" работата си, за да настрои нещо.

## §5. User Flows

Форматът е: стъпки, брой кликове, точки на отказ. Целите за кликове са дизайн бюджети — надвишаването им изисква обосновка.

### F1. Първо измерване върху карта (North Star flow, цел < 60 сек)

| # | Стъпка | UI | Кликове |
|---|--------|----|---------|
| 1 | Home → "Start on a map" | Голяма карта-афорданс | 1 |
| 2 | Търсене на адрес/място | Search field, автофокус (Maps идиом, P7) | въвеждане + Enter |
| 3 | Картата се центрира; dock-ът подсказва Polygon (пулс еднократно) | Onboarding слой O6 | 0 |
| 4 | Клик на Polygon (или клавиш P) | Dock | 1 |
| 5 | Клик по ъглите на парцела; площта тече на живо до курсора | Canvas + live label | n кликa |
| 6 | Затваряне: клик на първия връх / двоен клик / Enter | Canvas | 1 |
| 7 | Готово: MeasurementChip с площ+периметър стои на фигурата | — | 0 |

**Общо UI кликове (без върховете): 3.** Няма диалог, няма избор на единици (умни defaults по локация: BG→метрична), няма именуване (auto "Area 1", преименуване inline по желание).

### F2. Import на изображение + календриране + измерване

1. Home → "Import a file" (или drag-and-drop върху цялото Home/Studio — винаги активен drop target). **1 клик / 0 при drop.**
2. Файлът се отваря като Surface. **CalibrationBar** се плъзга под топ лентата: *"Draw a line along a known distance"* — инструментът линия е вече армиран. Не е модал: потребителят може да игнорира и да чертае.
3. Потребителят тегли линия по позната дължина (стена, мащабна лента на чертежа) → inline поле: `[____] m ▾` → Enter. **Календрирано с 1 чертане + 1 въвеждане.**
4. Ако пропусне календрирането: измерванията работят, но показват `px` и chip-овете са в warning стил с клик-към-календриране. Нищо не е блокирано.
5. ScaleChip в статус лентата показва постоянно `1 px = 0.048 m` (или `1:200` за PDF); клик → рекалибриране.

**Обосновка:** Това е анти-SketchAndCalc витрината (P10). Календрирането не е порта, а придружител: блокиращите wizard-и наказват потребителя, преди да е видял стойност. Сanity check: ако мащабът внушава абсурд (стая 2 km), ненатрапчив warning (§16).

### F3. Смяна на Workspace

1. Клик на workspace chip в топ лентата ("General ▾"). **1 клик.**
2. Popover: списък workspaces с едноредово описание + preview на какво се променя.
3. Избор → панелите/шаблоните/отчетите се сменят с кратка преходна анимация. Данните и инструментите — непокътнати. Обратимо със същите 2 клика.

Детайли в §19.

### F4. Инсталиране и ползване на Extension

1. Десен панел → таб Extensions → "Browse marketplace" (или ⌘K → "paint"). **2 клика.**
2. Overlay галерия (O2); карта на extension с: какво прави, **какви данни чете** ("Reads: area, perimeter"), от кого е. → Install. **2 клика.**
3. Extension-ът се появява като секция в десния панел. Селектираш измерване → extension-ът показва изчислението си върху неговите данни (Paint Calculator: площ × слоеве → литри).

**Обосновка:** Extension = панел, който консумира селекция. Никога собствен екран, никога собствен toolbar слот по подразбиране (P15, анти-Miro-sprawl). Данновият договор е видим, защото Bible постановява "Extensions не измерват повторно" — UI-ят прави правилото проверимо от потребителя.

### F5. AI Boundary Detection

1. Dock → AI инструмент (✦) или ⌘K → "Detect boundary". **1 клик.**
2. Клик върху обект на повърхността (покрив, парцел, стая).
3. **Ghost предложение**: пунктирана фигура в AI цвят, с confidence етикет и live площ. Платното не е блокирано.
4. Действия: `Enter`/клик "Accept" → става нормално измерване (с AI badge в provenance); влачене на връх → веднага става редактируемо и приемането е имплицитно; `Esc` → изчезва без следа.

Детайли в §18. **Обосновка:** Bible: "AI не извършва необратими действия без потвърждение." Ghost моделът прави потвърждението пространствено и едножестово вместо диалогово.

### F6. Export / Report

1. Топ лента → Export. **1 клик.**
2. Overlay O3: preview + формат (PNG / PDF / CSV / JSON — по Bible Export Engine) + Workspace-овият report template по подразбиране.
3. Download / share линк. **2 клика.**

### F7. Разделяне на парцел на части (Split, PD-009)

| # | Стъпка | UI | Кликове |
|---|--------|----|---------|
| 1 | Селекция на полигона → Split | Контекстно меню / ⌘K "Split" / клавиш `X` при селекция | 2 |
| 2 | Split режим: курсорът става разделител; тегли се линия (или полилиния за неправилна делба) през полигона; краищата snap-ват към ръбовете му | Canvas; ръководен ред под TopBar: "Draw a line across the shape" | n кликa |
| 3 | **Live preview**: още докато линията се тегли, частите се показват като ghost зони с течащи площи от двете страни | Ghost стил (пунктир, без commit) | 0 |
| 4 | `Enter` потвърждава → частите стават дъщерни измервания; повторение за следваща делба (3 части = 2 линии) | Canvas + chips на всяка част | 1 |
| 5 | Measurement List показва родителя като група: `Parcel ▸ Part 1 / Part 2 / Part 3`, всяка с площ; сумата на частите ≡ площта на родителя (по конструкция) | Ляв панел | 0 |

Правила: линия, която не пресича полигона от ръб до ръб, не активира Enter (hint: "Extend the line across the shape"); `Esc` разтваря без следа; Undo връща цялото на една стъпка; частите са пълноценни измервания (преименуване, цвят, extensions върху всяка). **Split не измества ръчния път** (PD-009): чертането на частите като самостоятелни полигони със snap остава винаги възможно — за случаи, когато частите не покриват цялото, застъпват се умишлено, или потребителят просто предпочита така. Никакъв UI не подканя към Split, когато потребителят чертае ръчно.

**Обосновка:** Live preview на площите (стъпка 3) е ключовата стойност за Real Estate: потребителят *мести линията и гледа квадратурите в реално време*, което покрива и „искам частите приблизително равни" без отделна функция (точното равно деление е висящо решение P-07). Ghost→commit моделът е същият като при AI (§18) — един ментален модел за всичко непотвърдено. Груповата цялост (сума на частите = родителя) е гаранция, която ръчното чертане никога не дава — това е разликата между картинка и делба.

## §7. High-Fidelity Mockups

Hi-fi mockup на Studio (W1 състоянието) е доставен като интерактивен HTML artifact — виж линка в придружаващото резюме. Реализира визуалния език от [16_DESIGN_SYSTEM.md](16_DESIGN_SYSTEM.md): tokens, светла/тъмна тема, MeasurementChip, ToolDock, панели. Mockup-ът е референтна картина, не код за production.

## §12. Accessibility (WCAG 2.2 AA)

Каnvas продуктите традиционно са a11y пустиня. Нашето структурно предимство: **Measurement List-ът (P4) е пълноценна алтернатива на платното** — всичко, което може да се направи с мишка върху фигура, има еквивалент в списъка (селекция, преименуване, изтриване, преглед на стойности, фокусиране).

Изисквания:
1. **Клавиатурно чертане**: армиране на инструмент → стрелки местят курсора-прицел (Shift=едри стъпки) → Enter поставя връх → Enter×2 затваря. Не е бързо; трябва да е *възможно*.
2. **Live region announcements**: "Vertex added. Area so far: 84 square meters." / "Polygon closed. Area: 124.5 square meters." Екранният четец получава същата обратна връзка, която окото получава от live label-а.
3. **Фокус върху canvas обекти**: Tab обхожда измерванията (в списъчен ред); фокусираната фигура получава видим фокус-ринг, различен от селекционния.
4. Контраст: текст ≥4.5:1, UI компоненти и фигурни контури ≥3:1 върху произволен фон → chips имат непрозрачна подложка (никога гол текст върху сателитна снимка).
5. Цветът никога не е единствен носител: фигурите се различават и по етикет+номер; статусите имат икона+текст.
6. Цели: ≥24×24 px pointer, ≥44×44 px touch. Vertex handles на touch се уголемяват при доближаване (loupe, §21).
7. `prefers-reduced-motion` изключва преходните анимации; live стойностите остават (те са информация, не декорация).
8. Пълна работа без мишка: всяко действие в ⌘K или в списъка.

## §14. Interaction Patterns

1. **Draw → auto-select**: завършена фигура се самоселектира и връща в Select (Excalidraw). `⇧`+инструмент задържа инструмента за серийно чертане (roofing/landscaping нужда).
2. **Live computation**: стойността тече до курсора по време на чертане; сегментните дължини се показват на всяка страна при чертане и селекция.
3. **Snap (Drawing Engine)**: към върхове, ръбове, ъгли 0/45/90°, и към mapping grid при карти. AutoCAD-стил визуални маркери (P8): различен глиф за връх/ръб/ъгъл. `⌥` временно изключва.
4. **Двоен клик = навътре** (Figma): върху фигура → vertex editing; върху etiket → преименуване; върху стойност в списъка → редакция.
5. **Директна манипулация преди панели**: влачене на връх, на ръб (добавя връх), на фигура; ротация през дръжка. Панелът е за точност, платното — за скорост.
6. **Контекстно меню** (десен клик/long-press): второстепенни действия за селекцията (duplicate, lock, група, изпращане към extension). Никога единствен път към функция (анти-P16).
7. **Undo/Redo е глобален и безусловен** — включва календриране, AI accept, изтривания. "No unnecessary dialogs" е възможно само защото undo покрива грешките: диалозите за потвърждение се заменят с toast + Undo бутон (8 сек).
8. **Drag & drop навсякъде**: файл, пуснат върху което и да е състояние на приложението, става Surface.
9. **Инерционен pan, pinch zoom, scroll zoom** — Maps идиоми без изненади.

## §16. Error States

Принципи: грешката се показва *където* е проблемът; винаги има следваща стъпка; тонът е човешки; никакви blame-съобщения.

| Случай | UX |
|--------|----|
| Неподдържан/повреден файл | Toast + inline карта на мястото на несъстоялата се Surface: какво се случи, кои формати поддържаме, "Try another file" |

| Изтриване | Без потвърждаващ диалог — toast с Undo (8 сек). Изключение: изтриване на цял проект (истински необратимо) → единственият разрешен confirm диалог в продукта |

## §18. AI Interaction Design

### Предизвикателство към брифа
Брифът казва "AI-first". Bible казва "AI подпомага потребителя" (Guardrail 7: подпомага, не замества). Разликата е съществена: AI-first четено като "AI е основният интерфейс" (chat-first) би нарушило Visual First и би сринало доверието в измерителен продукт. **Проектирам "AI-forward": AI е навсякъде достъпен, никъде задължителен, и никога не комитва.** Ако PO иска буквален AI-first интерфейс — това е PD решение, което променя Bible.

### Моделът: Ghost → Commit

1. **Всяко AI действие произвежда ghost**: пунктиран контур в AI цвят, `~` пред стойностите, confidence етикет. Ghost-ът не влиза в Measurement List, не влиза в суми, не се export-ва.
2. **Commit е човешки жест**: Enter / ✓ / докосване-редакция на връх (редакцията имплицитно приема — потребителят вече го е направил свое). Esc разтваря ghost-а безследно.
3. **Provenance badge завинаги**: AI-родено измерване носи ✦ в списъка и панела. Одитируемост за professional отчети; и честност — продуктът не се преструва, че потребителят го е начертал.
4. **Несигурността е видима**: confidence % на ghost етикета; под праг (напр. <60%) AI изобщо не предлага, а казва "Draw it manually — I'm not confident here". По-добре отказ, отколкото уверена грешка (доверието е марката, 07 §10 извод).
5. **Входни точки**: dock ✦ (клик върху обект), ⌘K глаголи ("detect rooms", "detect roof"), и пасивни предложения — chip в ъгъла ("✦ 3 similar roofs found — review?"), никога автоматично нарисувани.
6. **Batch accept** (за Room/Object Detection): ghosts се приемат поединично, всички наведнъж, или през списък с чекбокси в десния панел — но default-ът е преглед един по един.

**Обосновка:** Bible guardrail (без необратими действия без потвърждение) е изпълнен *пространствено*, не диалогово — потвърждението е на самото платно, в потока, а не прекъсване на потока.

## §19. Workspace Switching

### Модел: "Леща, не ключалка"

- Workspace-ът **не се избира при onboarding**. Всеки започва в General. **Обосновка:** форсиран избор на професия преди първата стойност е триене точно там, където Zero Learning Curve обещава нула; и начинаещият няма как да знае какво значи изборът, преди да е ползвал продукта.
- Смяната е в топ лентата (workspace chip, F3): popover с описание какво ще се промени. Prevew, не изненада.
- **Какво се сменя** (по Bible): панелни секции, шаблони, отчетни templates, настройки/defaults (единици, точност, цветова палитра на измерванията). **Какво никога не се сменя:** Tool Dock, позициите на панелите, клавишите, данните. Мускулна памет = константа (§2.2).
- Смяната е моментална, обратима, per-project (проектът помни своя workspace; default-ът за нови проекти се помни per-user).
- Ненатрапчива интелигентност: ако проект съдържа предимно покривни измервания, General може да покаже пасивен chip "Try the Roofing workspace" — веднъж, dismissible. [Зависи от AI Smart Suggestions по Bible.]

### Предизвикателство към слаба идея
"Workspace = различен интерфейс" от Bible може да се прочете като различни toolbar-и/layout-и per професия. Отхвърлям това четене: то умножава поддръжката (8 UI-я), чупи преносимостта на умението и противоречи на "едно ядро". Спецификацията фиксира: workspace варира *съдържание в стабилни контейнери*, не структура. Ако PO е имал предвид буквално различни интерфейси — нужно е изрично PD решение.

## §20. Extension Marketplace UX

- **Вход**: десен панел → Extensions таб → Browse; или ⌘K. Marketplace е overlay (O2), не сайт и не отделен екран — контекстът на работата остава под него.
- **Картата на extension** съдържа: име, едно изречение, screenshot, издател, **данновия договор** ("Reads: area, perimeter · Never modifies your measurements") и релевантните workspaces. Данновият договор е UI-ръбът на Bible правилото "Extensions използват вече изчислени данни".
- **Install = 1 клик**, без рестарт: extension-ът се появява като секция в десния панел и (по избор на потребителя, не на extension-а) като слот в контекстното меню.
- **UI бюджет на extension** (анти-Miro-sprawl, P15): една секция в десния панел + опционален ред в контекстното меню. Никакви toolbar слотове, никакви плаващи прозорци, никакви banners. Extension, който "иска повече място", иска всъщност да е workspace съдържание — различен разговор с различен собственик.
- **Изход**: uninstall от същото място, мигновен, без следи в проекта (изчисленията на extension-а са derived, не съхранени в измерването).
- Filtriране по текущ workspace по подразбиране ("Show all" винаги видимо).
- [A3] v1 = first-party каталог. Целият UX по-горе не се променя при отваряне към трети страни — добавят се само trust сигнали (издател, преглед, permissions), заложени в картата от ден 1.

## §21. Future Mobile UX (<768px)

Мобилният е **пълноценен измерител, редуциран редактор**: всичко се вижда и мери; тежката организация (групи, отчети, batch операции) остава удобна на голям екран. Това е UX позиция, не техническо ограничение — PWA-то е същото приложение.

1. **Dock остава долу** — на палечна дистанция (P3 печалбата); слотовете се редуцират до: Select · Polygon · Rect · Distance · ✦ · ⋯ (останалите в ⋯ sheet).
2. **Прецизно поставяне на връх с палец = loupe**: докосване-и-задържане показва лупа с offset прицел (iOS text cursor идиом); влаченето позиционира, пускането поставя. Хаптика при snap.
3. **Едно докосване никога не чертае** без армиран инструмент; two-finger = pan/zoom винаги, без конфликт с чертане.
4. Панелите → bottom sheets (peek: MeasurementChip лента със сумата; swipe up: пълният списък).
5. CalibrationBar → пълноширинна лента над дока; числовият вход отваря цифрова клавиатура.
6. Ghost accept: ✓/✕ бутони до фигурата стават 44px и се поместват над дока.
7. Камера като Surface източник [Bible: изображения; камерата е стандартният мобилен път към изображение] — заснемаш план/обект → мериш. Отбелязано като уточнение, не нова функция; изисква PO потвърждение.
