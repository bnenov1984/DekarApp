# 07 — Competitive & Pattern Analysis

**Статус:** Draft v1 за одобрение от PO
**Автор:** Lead Product Designer
**Цел:** Не копираме конкуренти (Guardrail 9). Анализираме ги, за да извлечем *интеракционни модели*, които са доказани, и *грешки*, които няма да повторим. Изводите директно захранват 15_UX_SPECIFICATION.

**Метод:** Всеки продукт е оценен по 8 измерения: силни страни, слабости, interaction patterns, навигация, информационна плътност, организация на toolbar, property панели, workflows. Анализът е по документирано състояние на продуктите към началото на 2026 г.

---

## 1. Figma

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | Еталон за canvas-first UX. Контекстният десен панел се появява само при селекция. Command palette прави всичко откриваемо без менюта. Мултиплейър без режими. |
| **Слабости** | Десният панел натрупва плътност с годините; за начинаещ Auto Layout е стена. Крива на учене над средната. |
| **Interaction patterns** | Селекция = център на всичко; двоен клик = навлизане в по-дълбоко ниво (vector edit mode); Space = pan; едноклавишни tool shortcuts. |
| **Навигация** | Файлов браузър → editor. Две нива, плоско. Всичко останало е overlay. |
| **Инф. плътност** | Ниска на платното, средна-висока в панелите. Плътността расте *с действието на потребителя*, не преди него. |
| **Toolbar** | Тесен горен toolbar с групирани инструменти (dropdown за варианти). ~9 видими слота. |
| **Property панели** | Дясно, секционни, контекстни на селекцията. Числови полета с drag-to-scrub. |
| **Workflows** | Draw → select → refine → share. Никакви wizard-и. |

**Извод за AreaFlow:** контекстен property панел при селекция; двоен клик за vertex editing; command palette като гръбнак на откриваемостта.

## 2. Canva

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | Най-ниската бариера в индустрията. Template-first старт. Контекстният toolbar се появява *над* селектирания обект. Дружелюбен език. |
| **Слабости** | Непрецизна; клавиатурата е втора класа; pro потребителите я надрастват. |
| **Interaction patterns** | Клик = селекция + контекстен toolbar; drag-and-drop от ляв каталог. |
| **Навигация** | Home с търсене и шаблони → editor. |
| **Инф. плътност** | Много ниска. Голяма типография, големи цели. |
| **Toolbar** | Контекстен, хоризонтален, над обекта. Постоянният ляв панел е каталог, не инструменти. |
| **Property панели** | Минимални, изникват при нужда. |
| **Workflows** | Wizard-ъобразни, оптимизирани за "готово за 5 минути". |

**Извод:** тонът и празните състояния на AreaFlow трябва да са "Canva-дружелюбни"; но прецизността не бива да се жертва — Canva показва докъде НЕ трябва да опростяваме.

## 3. Google Maps

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | Най-масово наученият пространствен идиом в света: pan/zoom/search. Почти нулев chrome. Контекстните карти се появяват при действие. |
| **Слабости** | Функцията "Measure distance" е скрита в десен клик — образцов пример за погребана функционалност. Измерванията не се пазят. |
| **Interaction patterns** | Search-first; десен клик за контекстно меню; плаващи карти върху картата. |
| **Навигация** | Един екран. Всичко е overlay. |
| **Инф. плътност** | Динамична — расте със zoom (де факто progressive disclosure по мащаб). |
| **Toolbar** | Почти няма. 3–4 плаващи бутона. |
| **Property панели** | Плаващи cards, не панели. |
| **Workflows** | Търсене → карта → действие. Под 3 клика до всичко масово. |

**Извод:** map режимът на AreaFlow трябва да започва с търсене на локация; scale bar конвенцията е задължителна; измерването при нас е първокласно, не погребано — това е директна диференциация.

## 4. AutoCAD Web

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | Прецизен числов вход по време на чертане (дължина+ъгъл). Command line за експерти. Слоеве. Доверие на професионалистите. |
| **Слабости** | Плашещ за неспециалисти. Модални работни потоци. Плътни ленти. Bible изрично го сочи като анти-модел. |
| **Interaction patterns** | Команден вход; object snap с визуални маркери (endpoint/midpoint) — това е златен стандарт за snap UX. |
| **Навигация** | Файлове → editor с ribbon-lite. |
| **Инф. плътност** | Висока навсякъде, още преди потребителят да е направил нещо. |
| **Toolbar** | Ribbon-производна, групи с падащи менюта. |
| **Property панели** | Постоянни, таблични, плътни. |
| **Workflows** | Command-driven; изисква предварително знание. |

**Извод:** открадваме само две неща — snap маркерите и *възможността* за числов вход при чертане (за професионалисти, скрита от начинаещите). Всичко останало е списък "какво да не правим".

## 5. Bluebeam (Revu)

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | **Markup List** — таблица на всички измервания, двупосочно свързана с платното (клик в реда → селектира на екрана). Това е най-ценният единичен pattern за AreaFlow. Tool Chest (запазени преизползваеми инструменти). Календрирането на PDF мащаб е индустриален стандарт. |
| **Слабости** | Смазващи toolbar-и; Windows-ера интерфейс; тежък onboarding. |
| **Interaction patterns** | Измерване като обект с данни; групиране/филтриране на измервания; суми по колони. |
| **Навигация** | Tabbed documents + docked панели отвсякъде. |
| **Инф. плътност** | Много висока. |
| **Toolbar** | Множество редове, конфигурируеми — свобода, която ражда хаос. |
| **Property панели** | Docked, плътни, мощни. |
| **Workflows** | Calibrate → measure → списък → отчет. Работният поток е правилен; опаковката е остаряла. |

**Извод:** Measurement List (двупосочно свързан с платното) става ядрен компонент на AreaFlow — той е и professional данновият изглед, и accessibility алтернативата на платното. Календрирането — да, но inline, не в диалог.

## 6. ArcGIS (Online / Pro)

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | Слоевият модел за геоданни; basemap switcher; коректност на координатни системи и мерни единици. |
| **Слабости** | Експертна сложност; терминология-бариера ("geoprocessing", "feature class"); бавни, тежки екрани. |
| **Interaction patterns** | Layer-centric всичко; таблици на атрибути, свързани с геометрии. |
| **Навигация** | Дълбока, модулна, много входни точки. |
| **Инф. плътност** | Висока до непроходима. |
| **Toolbar** | Ribbon (Pro) / модулни ленти (Online). |
| **Property панели** | Мощни, но многостъпкови. |
| **Workflows** | GIS-професионални, невъзможни без обучение. |

**Извод:** basemap switcher-ът и уважението към единици/CRS влизат в AreaFlow; терминологията и дълбочината — не. Surveying workspace ще изкушава към ArcGIS-изация — guardrail-ът "простота > функции" трябва да го удържи.

## 7. Miro

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | Плаваща вертикална лента вляво с малко слота; контекстен toolbar при селекция; отличен zoom/pan на голямо платно; лек onboarding. |
| **Слабости** | Разрастване на инструментите с годините (apps, шаблони, AI) размива минимализма — предупредителна история за Extensions стратегията ни. |
| **Interaction patterns** | Селекция → плаващ контекстен toolbar; drag от лентата към платното. |
| **Навигация** | Boards списък → board. Плоска. |
| **Инф. плътност** | Ниска на платно, средна в панели. |
| **Toolbar** | Вертикален ляв dock, ~8 слота, разширения в "още". |
| **Property панели** | Контекстни, плаващи. |
| **Workflows** | Свободни, неструктурирани. |

**Извод:** доказателство, че dock с ≤8 слота стига за богат продукт. И предупреждение: разширяемостта без UX бюджет изяжда минимализма — Marketplace-ът ни трябва да има "цена на видимост" за всяко разширение.

## 8. FigJam

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | **Долен централен tool dock** — ергономичен за мишка и палец, естествено съвместим с touch; работи и на таблет без промяна на модела. Игрив, нискобариерен. |
| **Слабости** | Умишлено плитък — не е модел за professional дълбочина, само за входно ниво. |
| **Interaction patterns** | Взимаш от дока → поставяш; едноклавишни shortcuts. |
| **Навигация** | Като Figma. |
| **Инф. плътност** | Много ниска. |
| **Toolbar** | Долен централен, ~7 слота, вариантите в popover над слота. |
| **Property панели** | Минимални плаващи. |
| **Workflows** | Съвместни сесии, бърз вход. |

**Извод:** долният централен dock е нашият основен кандидат за primary toolbar — единственият pattern, който оцелява без промяна от desktop до таблет (директна инвестиция в PWA стратегията, PD-001).

## 9. Excalidraw

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | Най-близкото до буквален "Zero Learning Curve" в индустрията: отваряш и чертаеш за секунди. Едноклавишни инструменти (R, O, A, L). Local-first. Островен toolbar, минимален chrome. |
| **Слабости** | Никаква прецизност, никакви данни, никаква професионална дълбочина — по дизайн. |
| **Interaction patterns** | Tool → draw → auto-връщане към селекция; Alt/Shift модификатори. |
| **Навигация** | Един екран. Точка. |
| **Инф. плътност** | Минимална. |
| **Toolbar** | Горен остров, ~9 слота, само икони + tooltip с shortcut. |
| **Property панели** | Ляв плаващ остров само при активна селекция/инструмент. |
| **Workflows** | Незабавни. |

**Извод:** еталонът за първите 60 секунди на AreaFlow. Ако първото измерване при нас изисква повече мисъл, отколкото първият правоъгълник в Excalidraw — не сме изпълнили философията.

## 10. SketchAndCalc (директен конкурент)

| Измерение | Наблюдение |
|---|---|
| **Силни страни** | Доказано търсене: покрива точно нашата задача (площ върху изображения/карти); мащабиране по позната дължина; слоеве; лоялна niche аудитория; кривi (irregular areas) като запазена марка. |
| **Слабости** | Остарял визуален език; малки икони в претрупани ленти; **календрирането е модален, объркващ flow** (потвърдено от потребителски оплаквания); измерванията не са първокласни данни-обекти; няма модерни canvas идиоми (inertial pan, pinch, контекстна селекция); mobile версията е отделно, по-слабо преживяване; без AI; без разширяемост; Google Maps зависимостта личи в цената и лимитите. |
| **Interaction patterns** | Кликово чертане връх по връх; числов вход за мащаб в диалог; резултати в страничен панел, откъснати от платното. |
| **Навигация** | Единичен editor + менюта. |
| **Инф. плътност** | Средна, но лошо организирана — всичко видимо едновременно. |
| **Toolbar** | Класически icon grid ленти, без групиране по честота на употреба. |
| **Property панели** | Статични резултатни полета; без връзка селекция↔данни. |
| **Workflows** | Import → (мъчително) calibrate → draw → resultат. Правилни стъпки, неправилна опаковка. |

**Извод:** SketchAndCalc валидира пазара и ни подарява списък с точки на болка. Печелим не с повече функции, а с: (1) calibration без диалог, (2) измерването като жив обект на платното, (3) модерни canvas идиоми, (4) една кодова база за всички устройства.

| P4 | Двупосочен Measurement List (таблица↔платно) | Bluebeam | ✅ Adopt (модернизиран) | Professional данни + accessibility алтернатива на платното |
| P5 | Едноклавишни tool shortcuts | Excalidraw, Figma | ✅ Adopt | Minimal clicks за pro; невидими за начинаещи |

| P7 | Search-first вход за карти | Google Maps | ✅ Adopt | Най-наученият идиом; нулево обучение |
| P8 | Snap с визуални маркери | AutoCAD | ✅ Adopt (само визуалната част) | Прецизност без команден ред |

| P10 | Inline calibration bar (не диалог) | — (анти-SketchAndCalc) | ✅ Нов | Най-болезненият конкурентен flow става нашата витрина |
| P11 | Basemap switcher, scale bar | ArcGIS, Maps | ✅ Adopt | Индустриални конвенции; не се преоткриват |
| P12 | Template-first onboarding | Canva | ❌ Avoid | Нашият "template" е повърхността (карта/изображение); шаблоните са Workspace слой, не вход |

| P14 | Модални wizard-и | SketchAndCalc, AutoCAD | ❌ Avoid | "No unnecessary dialogs" |

## Конкурентна диференциация (какво никой не прави)

1. **Измерването като жив обект**: етикет с площ/периметър върху самата фигура, обновяващ се при всяко редактиране. Bluebeam го доближава, но в остаряла опаковка; никой не го прави с Figma-качество на интеракцията.
2. **Calibration без диалог**: нито един от 10-те продукта няма немодално, едностъпково календриране.
3. **Едно UX от телефон до desktop**: SketchAndCalc има две различни приложения; ние имаме един PWA (PD-001).
4. **AI с ghost-предложения върху платното** (виж 15, §18): AI функциите на конкурентите са или липсващи, или chat-базирани — никой не предлага пространствен accept/refine/reject модел.
