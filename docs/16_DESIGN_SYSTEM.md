# 16 — Design System

**Статус:** Draft v1 за одобрение от PO
**Обхват:** Design tokens, компонентна библиотека, иконография. Покрива deliverables 8–10 от UX брифа.
**Правило:** Никой екран не използва стил или компонент извън този документ. Токените са единственият източник на визуални стойности.

---

## §1. Визуален характер

Три думи, които решават всеки спор за стил: **спокоен, точен, дружелюбен.**

- *Спокоен*: платното е сцената; интерфейсът е в неутрални тонове, цветът е запазен за измервания и статуси. Никакви декоративни градиенти в chrome-а.
- *Точен*: измервателните стойности винаги в tabular numerals; подравняване по 4px мрежа; snap маркерите и дръжките са геометрично чисти.
- *Дружелюбен*: заоблени радиуси (Canva посока, не enterprise-остри ъгли), меки сенки, човешки microcopy.

Посока: Figma-дисциплина + Canva-топлина. Анти-посока: AutoCAD/Bluebeam плътност (по Bible).

## §2. Design Tokens

Naming: `--af-{категория}-{роля}-{вариант}`. Всички стойности имат светла и тъмна тема; токените са семантични (роля), не буквални (цвят).

| Token | Light | Dark | Употреба |
|-------|-------|------|----------|

### 2.3. Цвят — Измервания (данновата палитра)

8 CVD-безопасни, взаимно отличими цвята за фигури: `--af-meas-1…8`
`#2E7D32 · #1565C0 · #E65100 · #6A1B9A · #00838F · #C62828 · #4E342E · #37474F`
Правила: цветът се назначава автоматично циклично; ръчна смяна от панела; **цветът никога не е единствен идентификатор** (етикет+номер винаги присъстват — a11y §12 от 15). Контурите върху произволен фон получават 1px контра-ореол (`--af-surface-panel` на 60%).

### 2.5. Пространство, форма, дълбочина, движение

| Категория | Скала |
|-----------|-------|
| Spacing | 4px база: `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64` |
| Radius | `--af-radius-sm: 6` (полета, chips) · `md: 10` (карти, панели) · `lg: 16` (sheets, overlays) · `full` (пилули) |
| Elevation | 3 нива: `e1` панели (0 1px 2px), `e2` popover (0 4px 16px @8%), `e3` overlay (0 12px 40px @16%) — сенки, не рамки |
| Motion | `--af-dur-fast: 120ms` (hover, селекция) · `base: 200ms` (панели) · `slow: 320ms` (overlays); easing `cubic-bezier(0.2, 0, 0, 1)`; `prefers-reduced-motion` → 0ms без изключения |
| Z-scale | canvas 0 · chips 10 · ToolBar/панели 20 · popover 30 · overlay 40 · toast 50 |

## §3. Компонентна библиотека

Инвентар v1 — 24 компонента, групирани по слой. За всеки: анатомия, състояния, a11y бележка. (Пълни спецификации per компонент — в отделни файлове при Phase 2 detail pass.)

### 3.1. Studio ядро

**ToolBar** (до 2026-10-11: плаващ долен ToolDock) — вертикална лента по левия ръб, ~44px широка, на цялата височина между TopBar и StatusBar; прикачена (без radius, e1 като панелите), не плаваща. Само икони, слотове ≤10, разделители групират: навигация │ форми │ Split │ AI. Import не е слот — живее в TopBar. Състояния на слот: rest / hover (tooltip: име + shortcut) / active (filled икона + accent подчертаване) / disabled (Split без селекция — слотът остава на мястото си) / popover за варианти вдясно от слота. A11y: `role="toolbar"`, `aria-orientation="vertical"`, стрелки ↑↓ между слотовете.

**CanvasStage** — рендер повърхността. Отговаря за: pan/zoom trans, snap маркери (връх ◆ / ръб ▸ / ъгъл ∠), фокус-рингове на фигури, ghost слой. Не съдържа бизнес логика (Bible).

**MeasurementShape** — фигура на платното. Състояния: rest (цвят от палитрата, 2px контур, 12% fill) / hover (fill 20%) / selected (handles + accent double-контур) / vertex-editing (върхове като дръжки) / locked (пунктир къс) / ghost (AI: пунктир дълъг, `--af-ai`, без fill).

**MeasurementChip** — живият етикет върху фигурата: име + основна стойност (+ втора при селекция). Непрозрачна подложка (a11y контраст), radius-sm, свива се до само-стойност при малък zoom, изчезва под праг (декларира се в списъка). Warning вариант при некалибрирано (`px` стойности).

**CalibrationBar** — немодална лента, overlay над платното (не под TopBar — не измества tool bar/платно/дясна колона, §2.2, 2026-11-15). Състояния: prompt ("draw a line…") / input (число+единица, автофокус) / set (свива се в ScaleChip) / warning (подозрителен мащаб). Dismissible; връщане от ScaleChip.

**ScaleChip / StatusBar** — постоянната истина: мащаб, единици (клик = смяна), zoom, snap toggle, sync/offline статус. Всеки сегмент е интерактивен; височина 28px.

**ZoomMenu** — отваря се с клик върху zoom % в StatusBar (над него): поле за % (автофокус, текущата стойност е селектирана), Zoom to fit, 50%, 100%, 200%, Zoom in, Zoom out, с шортките вдясно. Затваря се с Enter (след прилагане), Escape или клик извън. Стъпка ×1.1 (същата като колелото, 15 §2.2), граници 10–800%.

**TopBar** — групи по вид, отляво надясно: лого/back · име на проект (inline rename) · WorkspaceSwitcher chip · Undo/Redo …… Share · Import · Export · акаунт (AccountMenu). Всички са flex деца на лентата — нищо не е `position: fixed` върху нея. Височина 48px, никога повече съдържание от това.

### 3.2. Панели и данни

**PanelShell** — дясната колона (280px): Properties горе — висока колкото съдържанието си (мин. 160px, макс. 65% от колоната), Layers долу взема остатъка; разделителят е ръчна корекция (влачене, ↑/↓), двоен клик връща автоматичната височина (2026-11-15). ≥1280: прикачена; 1024–1279: overlay, отварян от тясна лента по ръба; <1024 (само преглед, PD-022): overlay. Винаги присъства — празна секция показва кратък текст вместо да изчезва. Заглавията на секциите съдържат само заглавие, без действия. Tab скрива/показва страничните колони.

**MeasurementList** — гръбнакът (P4): ред = swatch + име + стойност (tabular) + provenance ✦ ако AI. Селекцията е двупосочна с платното. Footer: суми по видими/селектирани. Групиране по слой/тип; split части (PD-009) се показват като разгъваема група под родителя, редът на родителя показва пълната площ. A11y: пълноценна таблица, стрелки+Enter еквивалент на клик върху фигура.

**PropertyPanel** — контекстни секции за селекцията: Identity (име, цвят) / Values (area, perimeter, vertices — read-only стойности, редактируеми геометрии) / Split / Notes / Extensions (секциите на инсталираните) / "Delete shape" — ниско-акцентен бутон на цяла ширина, последен в потока на панела (не закачен). Split отваря формата за части като popover (SplitPopover, слоят popover от Z-scale) вляво от бутона, над платното (2026-11-15). Lock е само в реда на Layers. Multi-select: агрегирани стойности (сума на площите) + общите свойства.

**UnitField / NumberField** — числово поле с единица-суфикс dropdown; drag-to-scrub (Figma); стрелки ±; tabular. Валидация inline, никога alert.

**SegmentedControl, Toggle, Select, SearchField** — стандартни, по токените; SearchField с ⌘K вариант (глобален) и локален (списък, marketplace).

### 3.3. System слой

**CommandPalette** — overlay (e3): fuzzy търсене на действия/инструменти/измервания/workspaces/extensions/help; резултатите показват shortcut-а си (обучаващ страничен ефект). Секционирани резултати, recent на празно поле.

**Toast** — долу-център над платното; варианти info/success/warning/danger; винаги с действие когато е приложимо (Undo 8 сек). Никога не застъпва StatusBar (offset нагоре).

**Banner** — вграден в платно/панел за трайни състояния (offline, uncalibrated).

**Modal** — съществува в библиотеката с една узаконена употреба: изтриване на проект (D7 от 15). Всяка нова употреба минава през design review.

**Sheet** — мобилен/таблет контейнер (bottom/side); peek + full състояния.

**EmptyState** — икона + едно изречение + primary действие (по §15 от 15).

**Tooltip / Kbd** — tooltip = име + `Kbd` клипче; задължителен за всеки икона-само бутон (a11y + откриваемост).

**ProgressChip** — отменимо микро-съобщение за фонови процеси ("✦ Detecting… ✕", "Rendering PDF… ✕").

### 3.4. Marketplace / Extensions

**ExtensionCard** — име, изречение, издател, screenshot, **PermissionTag ред** ("Reads: area, perimeter"), workspaces, Install/Installed. Състояния: rest / installing / installed / update.

**ExtensionPanelSection** — контейнерът, в който extension живее в PropertyPanel: заглавие с ✦/икона, тяло (изчисления върху селекцията), footer линк към настройки. Това е *целият* разрешен UI на extension (D9).

**PermissionTag** — микро-компонент на данновия договор; изброява четените стойности; вариант danger ако бъдещ extension поиска запис (v1: не съществува такъв).

## §4. Iconography

- **Мрежа:** 24×24, зона на съдържание 20×20, stroke 1.75px, заоблени краища/съединения. Двойка стилове: **outline = неактивно, filled = активен инструмент** (ToolBar-ът комуникира състояние без цвят — a11y).
- **Геометрична честност:** иконите на инструментите са самите форми (полигон, кръг, крива) без метафори. Инструмент за измерване на разстояние = линия с върхове-точки, не линийка-клипарт.
- **Резервирани глифове:** ✦ (четирилъчева искра) = само AI (в цвят `--af-ai` където е възможно); ⚖/scale глиф = само календриране; ◆▸∠ = само snap маркери.
- **Източник:** база Lucide (open, консистентен stroke), разширена с ~12 custom глифа: polygon, curve, freehand, distance, area, perimeter, angle, radius, calibrate, layer-surface, workspace, ghost-accept. Custom сетът следва Lucide метриките, за да е неразличим.
- Всички икони имат текстов еквивалент (tooltip + aria-label); икона без етикет не съществува в продукта.
- Размери: 16 (статус лента, списъци) / 20 (панели) / 24 (ToolBar). Touch размери отпадат с PD-022 (мобилно = само преглед).

## §5. Тъмна тема

Не е инверсия, а втора първокласна тема (map/сателитна работа вечер е реален сценарий на професионалистите):
- Платното диктува: върху тъмни сателитни снимки chrome-ът в dark стои по-ниско контрастно от снимката — правилно; в light темата панелите не бива да засенчват светли чертежи.
- Измервателната палитра (2.3) се преизчислява за тъмен фон (по-високи luminance стойности), не се преизползва.
- Автоматично следва системата; ръчен override в Settings; per-проект override няма (излишна сложност).

---

## §6. Управление на системата

- Токените живеят като JSON (style-dictionary формат) → CSS variables + документация се генерират; никакви магически стойности в код.
- Компонент влиза в библиотеката само с: анатомия, всички състояния, a11y бележки, dark вариант, мобилно поведение.
- Промяна на token = design review; промяна на компонент = преглед на всички употреби.
- Versioning: системата се версионира отделно от продукта (semver); breaking визуални промени = major.
